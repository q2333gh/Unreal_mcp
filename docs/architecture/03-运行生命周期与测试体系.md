# 运行生命周期与测试体系（Lifecycle & Verification）

## 1. 启动到退出的生命周期

### 启动阶段
`startStdioServer()` 在创建 server 后：
- 建立 stdio transport 连接
- 注册 `SIGINT/SIGTERM` 处理
- 挂钩 `beforeExit/exit` 做兜底清理
- 可选记录 JSON-RPC stdout 片段（debug）

因此服务具备“优雅停机 + 异常兜底”双路径。】.【F:src/index.ts†L183-L296】

### 退出阶段
统一调用顺序为：
1. 停止 automation bridge
2. 释放 Unreal bridge
3. 关闭 metrics server
4. 停止 GraphQL server
5. 尝试关闭 MCP server transport

这避免资源泄露和端口残留。】.【F:src/index.ts†L194-L253】

## 2. AutomationBridge 的连接策略要点
`AutomationBridge` 构造阶段做了大量安全/鲁棒处理：
- host 规范化（默认仅 loopback；非 loopback 需显式环境变量开启）
- port 列表清洗、去重与回退
- 协议协商列表聚合（默认 + 用户配置 + 环境变量）
- 多项上限参数（并发、队列、速率）统一初始化

其本质是“**输入约束先于网络连接**”。】.【F:src/automation/bridge.ts†L41-L76】【F:src/automation/bridge.ts†L78-L171】【F:src/automation/bridge.ts†L172-L260】

## 3. UE 插件侧生命周期保护
C++ 子系统层面：
- commandlet 模式不启动网络桥，避免影响 cook/package。
- `Tick` 仅在安全窗口处理 pending 请求。
- `Deinitialize` 防御式释放 ticker、连接管理器、日志设备。

对 UE 编辑器生态而言，这些处理直接关系到稳定性。】.【F:plugins/McpAutomationBridge/Source/McpAutomationBridge/Private/McpAutomationBridgeSubsystem.cpp†L77-L122】【F:plugins/McpAutomationBridge/Source/McpAutomationBridge/Private/McpAutomationBridgeSubsystem.cpp†L132-L176】【F:plugins/McpAutomationBridge/Source/McpAutomationBridge/Private/McpAutomationBridgeSubsystem.cpp†L216-L229】

## 4. 测试体系：单测 + 自定义集成 Runner
`tests/test-runner.mjs` 展示了集成测试框架特点：
- 使用 MCP client + stdio transport 真实调用服务
- 支持通过环境变量切换 server 命令与启动参数
- 统一响应归一化（`normalizeMcpResponse`）
- 关键字+条件组合评估预期（含 `success|error` 这类复合预期）
- 输出汇总与报告落盘

这让测试可覆盖“协议层返回语义”，不仅是函数单元逻辑。】.【F:tests/test-runner.mjs†L1-L27】【F:tests/test-runner.mjs†L44-L71】【F:tests/test-runner.mjs†L128-L173】

## 5. 关键原理（面向维护者）

- **生命周期闭环**：启动装配清晰，退出路径完整。
- **网络边界安全**：默认 loopback，LAN 暴露必须显式开启。
- **编辑器状态感知**：在 unsafe state 延后处理请求。
- **协议级测试**：以 MCP 响应语义为断言对象，确保外部可用性。
